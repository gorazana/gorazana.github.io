Where this component stops

No arbitrary uploaded executable templates, office editor, universal PDF/A/signature certification, implicit cross-database snapshot consistency or embedding all office conversion engines in every app.

Model & lifecycle

Typed contracts, owned persistence and configuration are preserved in SOURCE_REFERENCE.md, original sections 5–6. Adapt to the actual implementation; these are not applied migrations.

Authorize template/data → validate schema and format capability → resolve immutable template/assets → freeze permitted data revision → persist generation intent → render in bounded sandbox → stream artifact and hash → publish ready receipt only after verified storage → serve through current authorized download. Retry uses the original template/data digest, not whatever template is newest today. Cancellation marks stop requested and cleans staging artifacts only after worker termination; do not remove an output another completed generation references. ### Honest output contracts `application/pdf` is not proof of PDF/A, accessibility tagging, cryptographic signing or archival conformity. Each claimed format/profile needs a selected renderer and independent validator. Do not promise arbitrary CSS behaves identically across Chromium and a native layout engine. PDF templates and HTML templates may share data contracts but remain explicit different renderer assets. Font files are application assets governed by their own licenses; do not redistribute unlicensed fonts in this package.

Operational requirements

Trusted HTML documents and optional bounded native layout adapter; no Docker dependency for HTML. Optional expanded profile: Gotenberg service, managed fonts, renderer isolation, document versions, bulk export/retry, retention and archive integration.
