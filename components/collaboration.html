Responsibilities & capabilities

This is a research contract. An implementation, tag or icon alone does not establish that every listed capability is shipped or verified.

  • COLLABORATION-01Document-scoped sessions and editing capabilities
  • COLLABORATION-02Explicit CRDT/OT provider and protocol/version compatibility matrix
  • COLLABORATION-03Snapshots, operation limits and compaction with recoverable checkpoints
  • COLLABORATION-04Presence and cursors separated from permanent content
  • COLLABORATION-05Revoked editor handling during offline reconnect and shared-link expiration
  • COLLABORATION-06Export and recovery without assuming all domain actions can merge

Where this component stops

Reusable contract and lifecycle only. Host identity, tenant admission, jurisdiction, detailed business schema and operational deployment remain application-owned. Optional ports are alternatives, not mandatory package dependencies.

Model & lifecycle

CollaborativeDocument, ChangeBatch, Snapshot, EditorLease, Conflict

Open authorized document -> submit changes -> merge according to declared engine -> checkpoint -> revoke or recover.

These are replaceable capability ports, not a blanket requirement to install every named package. Mandatory dependency claims require a tested implementation profile.

Operational requirements

Host-selected authoritative storage; workers, brokers or external services only where the selected adapter requires them. No mandatory paid provider. Declare capability and licensing limits before enabling an integration.

Safety & acceptance

  • Concurrent text convergence does not authorize business transitions
  • Old offline clients cannot restore revoked access
  • Compaction must preserve an explicit recovery path
  • Negative authorization, cross-scope list/detail/export and stale-revision cases
  • Duplicate, reordered, expired and concurrent requests for every consequential transition
  • Selected SQLite/PostgreSQL adapter migration, rollback and concurrency tests
  • Provider contract tests; fixtures and genuine live service evidence labeled separately
  • Accessible/narrow/keyboard frontend tests for each supported renderer
