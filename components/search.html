Where this component stops

Model & lifecycle

Typed contracts, owned persistence and configuration are preserved in SOURCE_REFERENCE.md, original sections 5–6. Adapt to the actual implementation; these are not applied migrations.

Source transaction appends versioned index event → worker compares revision → upsert/delete idempotently → advance checkpoint only after confirmed adapter write. Query resolves authoritative scope before backend call, validates allowed filters and ranking options, then hydrates accessible hits. If access cannot be represented before facets/counts, disable those outputs or use a backend that can enforce it; filtering only returned hits is insufficient. Reindex builds a new generation from snapshot+change log, catches up, verifies, then atomically switches active alias and retains old generation for bounded recovery. ### Security-sensitive aggregation A hidden record can leak through a count, facet label, spelling suggestion or highlighted text even when its row is dropped later. The backend authorization/filter contract must cover every output. When host policies are too complex to express in the index, return only current-authorized hydrated records without exact total/facets, or select a database-backed query strategy. Do not publish a false total computed from inaccessible hits.

Operational requirements

Native database backend with bounded prefix/full-text capabilities and no external search server. Optional expanded profile: External index adapter, scoped access tokens only if safe, blue/green reindex generations and lag monitoring.
