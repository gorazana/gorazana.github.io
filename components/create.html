Responsibilities & capabilities

This is a research contract. An implementation, tag or icon alone does not establish that every listed capability is shipped or verified.

  • CREATE-0132 conditional questions with rich/plain/noninteractive parity
  • CREATE-02Versioned recipe, lock, file plan and honest execution receipt
  • CREATE-03Capability-based package and business-module selection
  • CREATE-04Go HTML and independently verified Inertia Vue/React profiles
  • CREATE-05Safe source ownership, upgrades, consent and recovery

Where this component stops

Proposed working name. Build-time assembly over native Goravel and the real Package Skeleton; not a new runtime framework or mandatory package collection.

Model & lifecycle

Recipe, ResolutionLock, FilePlan, ExecutionReceipt, RegistryEntry

Read-only discovery -> resolve compatible choices -> review file/effect plan -> explicit consent -> stage/validate/promote -> handoff.

Dependencies, deliberately chosen

Native Goravel capabilities

  • Goravel full/lite installer
  • Package Skeleton generation/publication contracts
  • host-native provider/route/resource conventions

Go & candidate adapters

  • context
  • encoding/json
  • go/ast
  • go/parser
  • os/exec with bounded literal arguments
  • Skeleton-selected terminal library

Optional Gorazana integration ports

Package SkeletonModulesGorazineDefenderTenancyCMSCommerceAccounts (UMS)Records (DMS)

These are replaceable capability ports, not a blanket requirement to install every named package. Mandatory dependency claims require a tested implementation profile.

Operational requirements

Host-selected authoritative persistence and necessary native workers. External services are opt-in, with explicit credentials, costs and capability/evidence profiles.

Safety & acceptance

  • Research-only options cannot generate fake working apps
  • Secrets stay out of recipe/Git/logs
  • Migrations/deployment/remote creation are separate consent
  • Custom provider needs real conformance
  • No silent source overwrite or unsupported frontend conversion
  • Negative and boundary tests for each stated invariant
  • Concurrent/stale revision and duplicate-command tests for the principal transition
  • Real selected database transaction, migration-upgrade and recovery tests
  • Cross-scope list/detail/count/export/relationship checks
  • No real external side effects in ordinary fixtures; live-provider tests separately labeled
  • Selected renderer tested for validation, keyboard, narrow layout and error states
