Where this component stops

No new foundation model, universal autonomous agent with unrestricted shell, fabricated citations, guaranteed factual outputs, automatic compliance or a duplicate of native provider/streaming APIs.

Model & lifecycle

Typed contracts, owned persistence and configuration are preserved in SOURCE_REFERENCE.md, original sections 5–6. Adapt to the actual implementation; these are not applied migrations.

Resolve use-case policy/current scope → classify allowed inputs → reserve budget atomically → load authorized source revisions → construct bounded native SDK request → validate structured output and source citations → mark ready or needs_review → reconcile actual usage. Retrieved instructions remain data. Before any model-requested tool call, validate tool schema, current actor/scope, action-specific policy and required approval; record idempotency receipt around side effect. Timeout after provider processing may consume tokens; preserve uncertain accounting and reconcile rather than silently zeroing usage. ### Provider support is reused, not renamed Map each native SDK operation required by a use case to the actual installed public interface. An official adapter existing for a provider does not prove a model supports JSON schemas, tools, embeddings or streaming in the chosen combination. Maintain a capability matrix and fail unsupported requests explicitly. ### Human decision boundary School safeguarding, admissions, HR, finance and medical-like data require domain-specific review policies. Extraction can prepare a draft and evidence; it must not autonomously approve payment, alter student status or disclose another tenant's document. Model output is untrusted input that passes the same validation and authorization as a human request.

Operational requirements

Native SDK call adapter for one registered use case with output validation and budget cap; retrieval/providers optional. Optional expanded profile: Scoped retrieval index, durable extraction, approvals, evaluations, usage accounting and multiple native providers with explicit routing policy.
