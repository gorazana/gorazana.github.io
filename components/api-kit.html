Where this component stops

Not an API gateway, new router, automatic authorization engine, universal GraphQL server or a claim generated docs enforce request validation.

Model & lifecycle

Typed contracts, owned persistence and configuration are preserved in SOURCE_REFERENCE.md, original sections 5–6. Adapt to the actual implementation; these are not applied migrations.

Register typed route metadata during provider initialization → validate against actual native routes and unique operation IDs → freeze → generate deterministic OpenAPI. Runtime validation/controller executes native logic; errors map through registered safe categories to RFC 9457 shape. Cursor decode validates signature/version/expiry and exact query/scope before use; schema validation does not imply authorization. Request logging redacts sensitive headers/body fields and shares an opaque correlation ID. ### HTTP representation detail RFC 9457 responses should use `application/problem+json` when supported by the host response API. The shown controller is a proposed compile target; during implementation use the verified native API to set the correct content type and validate it over HTTP. A generic JSON helper alone may leave `application/json`, so add a real response conformance test rather than assuming the header. Preserve backwards-compatible error codes; changes to public semantics require an upgrade note.
