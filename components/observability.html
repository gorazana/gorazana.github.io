Where this component stops

No new global telemetry SDK, guaranteed detection of all incidents, public pprof, tenant IDs as metrics labels or claim health success proves all business workflows correct.

Model & lifecycle

Typed contracts, owned persistence and configuration are preserved in SOURCE_REFERENCE.md, original sections 5–6. Adapt to the actual implementation; these are not applied migrations.

Native provider registers health checks/instruments once → readiness request executes context-bounded checks with concurrency cap → aggregate required failures into 503 and optional failures into degraded according to config → return safe report. Detailed diagnostics require separate operator policy and redact before serialization. Telemetry export is asynchronous/bounded via the host stack; unavailable exporters never become an unbounded per-request retry loop. Startup detects incompatible known dependency combinations and refuses unsupported export profiles rather than suppressing warnings. ### Existing telemetry restrictions Earlier Defender/Tenancy handoffs described conditional telemetry dependency exceptions. Do not assume those findings remain current or have been fixed: inspect the actual selected module graph, run a fresh called-symbol scan and record whether native log export is supported. A passing root-module scan is not proof of a larger consuming application's dependency safety. Never re-enable an unsupported exporter just because this package adds metrics.

Operational requirements

Liveness/readiness and structured native logs without external telemetry backend. Optional expanded profile: Existing OTel collector integration, package SLO metrics, restricted diagnostics and job correlation; host owns export credentials and retention.
