Where this component stops

No PHP package loading, arbitrary runtime Go compilation, unsafe Go plugin loading, tenant-provided executable code, automatic marketplace execution, mandatory microservices, or business-domain ERP modules.

Model & lifecycle

Typed contracts, owned persistence and configuration are preserved in SOURCE_REFERENCE.md, original sections 5–6. Adapt to the actual implementation; these are not applied migrations.

Manifest planning is pure: validate IDs/ranges → verify registry imports exist → calculate the graph → produce a stable digest. Generated `bootstrap/modules.go` contains explicit imports and provider values; the host wires this list into its provider registration before boot. No request reloads providers. Lifecycle writes use compare-and-swap (CAS) revision checks and a durable operation ID. `requested → planned → migrating → ready → enabled`; failure records its last completed step and leaves availability false. Cross-database migrations are a saga, not one transaction: record each target receipt and resume idempotently. Disable first closes admission, then drains owned jobs, and only then records disabled; existing effects are not undone. Queued work carries module generation and must be re-admitted when executed. A disabled module retains its tables unless a separate destructive uninstall is approved. ### Host module layout (not the package repository itself) ```text modules/admissions/ module.json service_provider.go app/contracts/ app/models/ app/actions/ app/queries/ app/services/ app/http/controllers/ app/http/requests/ app/http/middleware/ database/migrations/ database/seeders/ database/factories/ config/ routes/web.go routes/api.go resources/views/ resources/js/ resources/lang/ tests/unit/ tests/feature/ bootstrap/modules.go ``` Use the host's root `go.mod` initially. Module packages use deterministic Go import paths under it; generated imports are updated explicitly. A packaged third-party module can be a separate Go dependency but still registers compiled providers. An installable archive that changes Go code requires rebuild/redeployment: document this plainly for desktop and server hosts. ### Manifest security and upgrades Reject arbitrary shell install scripts in manifests. Accept an explicit schema version, ID pattern `^[a-z][a-z0-9-]{0,62}$`, semantic version and declared dependency ranges. Cap external assets and prevent zip-slip when an optional distribution tool is later introduced. The graph digest includes manifest bytes and selected dependency versions, not secrets. Never let a tenant administrator choose a Go import path. Adopt expand/contract database upgrades; destructive down migrations require operator approval and a tested backup. ### Standard examples Provide a two-module inventory application plus a school admissions/learning pair. Examples must show a normal provider registration, module routes and a service call without requiring Admin. The paid-feature example injects a fake entitlement verifier explicitly marked test-only, plus a real signed-license adapter in a separate integration test when licensing exists. A boolean UI switch is never proof that an entitlement is valid.

Operational requirements

A single Go binary, static manifest registry, no module-state database until runtime enablement is explicitly requested. A conventional nonmodular Goravel app can install another ecosystem package without installing this package. Optional expanded profile: Optional persistent scope state, audited lifecycle commands, staged deployments, compatibility planning and Admin integration. Marketplace signing and external sidecars need separately tested adapters; they are not required to obtain basic modules.

Safety & acceptance

  • Current identity/admission and explicit-deny rules remain authoritative
  • Applied migrations stay immutable; sensitive state and audit share a declared transaction where claimed
  • Failures, retries, resource bounds, partial/unknown effects and source ownership are explicit
